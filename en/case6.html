Project Description

Project Description

Built-in internal CRM +

The platform has its own CRM: student and contact records, interaction history, subscriptions and accesses are linked to the client card without export to external services. You can see the full picture of a person - payments, chat messages, active programs and statuses - and work with the audience from one admin panel.

Unlimited video - S3 storage deployed +

The video library is not limited by the file limit per application: videos and covers are stored in S3 object storage. This makes it easier to scale the volume, unload the main server and organize output according to access policies. The storage connection is designed as a separate circuit: loading, issuing and rights to objects are not mixed with the business logic of the site itself.

Integration with payment system +

Payment acceptance is built in through a payment provider: the user pays for a subscription or access to the program on the provider’s side, and the platform receives confirmation via callback/webhook. After successful payment, the access status is updated automatically - without manually checking receipts. This reduces errors and speeds up the issuance of materials immediately after payment.

Subscription tracking (date and tariff) +

The system records which tariff the student has, the start and end date of the period, and the history of renewals. In the admin panel this can be seen in the user card; in your personal account - a clear status “up to what date paid” and the name of the current plan. This makes it easier to support the club model and answer questions about access without searching through correspondence.

Chat for communication with all students +

Communication is centralized within the platform: the master and students correspond without using third-party messengers. The message history is saved, making it easier to post announcements and replies to the program. Notifications and quick responses keep the entire course or club audience in regular contact.

Student's personal account +

Each student has a personal account: login using an account, a list of purchased or available programs, materials and videos by subscription. Subscription and access statuses, progress and activity within the platform are displayed. This reduces the support burden: the status and content are visible to the user independently.

Hidden videos inside the platform +

Some videos are not shown on the site’s public display: they are available only within the platform - for example, by club subscription, access level, or individual group. In the admin panel, visibility and viewing mode are set to separate open content from closed practices or private broadcasts.

Interface for creating events through the admin panel +

Events (retreats, meetings, offline or online events) are started from the admin panel: name, description, date and place, publication on an external website. After the event, you can upload a photo gallery - a separate set of pictures for each event, without mixing with the general media library. This is how visitors see a structured event feed with illustrations.

Blog - uploading articles and photos +

The blog is built into the platform: articles with text and images are created and edited from the admin panel, media is loaded into the content without a separate external CMS. The publication goes to the information section of the site in the same style as the rest of the project pages.
